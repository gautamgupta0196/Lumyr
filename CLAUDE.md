# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Lumyr is an open-source, local-first AI dashboard generator. Users describe
visualizations in natural language and an agent generates interactive Streamlit
dashboards. It's a desktop app built with Electron.

**It is standalone.** There is no backend server, no account system, and no
hosted service. Users supply their own Anthropic API key, which is stored
encrypted via Electron `safeStorage` and used to call the Anthropic API
directly from the main process.

Do not reintroduce a server hop, authentication, or usage metering — "runs
entirely on your machine" is the product's reason to exist.

## Development Commands

```bash
npm run dev              # Vite dev server + Electron
npm run build            # Full production build (tsc + vite + electron-builder)
npm run build:full       # Prepare Python + full build
npm run typecheck        # TypeScript validation
npm run lint             # ESLint for src/ and electron/
npm run test:unit        # Vitest unit tests
```

Python setup — dashboards run on a bundled Python, not a venv (a `.venv` is
refused unless `LUMYR_ALLOW_UNBUNDLED_PYTHON=1`):
```bash
npm run prepare:python   # downloads Python 3.11 + deps into resources/python-<platform>
```

## Key Directories

- `src/` — React renderer: components, hooks, Zustand store
- `electron/` — main process: data clients, agent, Python manager, IPC
- `electron/opencode/` — the opencode engine and its MCP data bridge
- `python/` — Streamlit runner that executes generated dashboard code
- `docs/` — GitHub Pages landing page (deployed by `.github/workflows/pages.yml`)
- `tests/unit/` — Vitest unit tests

## Generation Engine

Dashboards are generated by the open-source [opencode](https://opencode.ai)
agent, driven from `electron/opencode/provider.ts`:

1. `startMcpBridge` (`electron/opencode/mcp-bridge.ts`) stands up an MCP server
   on an ephemeral loopback port exposing `list_tables`, `get_table_schema`, and
   `run_sql` against the active connection. It runs **in-process** rather than as
   a stdio subprocess because its query callbacks close over live connection
   state a child process could not reach.
2. The provider passes the MCP config (the bridge plus any servers configured on
   the connection) to `createOpencode({ config })`. The SDK serializes it into
   `OPENCODE_CONFIG_CONTENT`, so there is no `opencode.json` to write.
3. `createOpencode` spawns the `opencode` binary from PATH. It does **not** set
   the child's cwd, so every request carries `query: { directory }` to bind it
   to the run's workspace. The user's key is injected with `client.auth.set`.
4. **`event.subscribe()` must also pass `query: { directory }`.** The server
   scopes its event stream exactly like its sessions; omit it and the agent runs
   and bills normally while the stream stays silent forever. A stall guard
   cancels the run if no event arrives for 180s.
5. The event stream is mapped to `AgentStep` objects and pushed to the renderer
   over the `agent:step` channel — the same contract the progress UI has always
   consumed.

The agent writes `app.py`; its contents are returned to the renderer, which
calls `streamlit.runCode()` to run it.

Cancellation: `claude:generate-agent` registers an `AbortController` in
`activeRuns` keyed by `runId`; `claude:cancel-agent` aborts it.

## Data Flow

1. User types a natural language query in the renderer
2. Renderer calls `window.electron.claude.generateAgent(request)`
3. Main process resolves the active connection and builds schema/query callbacks
4. The opencode agent inspects the schema and writes the dashboard
5. `PythonManager` spawns Streamlit; `DashboardViewer` renders it in an iframe

## IPC Channels

All Electron IPC uses the preload bridge pattern:
- `bigquery:*`, `postgresql:*`, `snowflake:*`, `redshift:*`, `netsuite:*`,
  `odbc:*` — data source operations
- `claude:*` — agent generation, cancellation, key validation
- `streamlit:*` — Python/Streamlit process control
- `dashboard:*` — CRUD for saved dashboards
- `connections:*` — manage multiple connections
- `settings:*` — API key, model, execution timeout

## State Management

- **Zustand store** (`src/stores/app-store.ts`): UI state, schema cache,
  generation state, conversation history
- **Electron store** (`electron/store.ts`): persistent settings plus encrypted
  credentials and the Anthropic API key

## Gotchas

- **IPC types are declared twice**: `electron/preload.ts` (the `ElectronAPI`
  interface) and `src/types/electron.d.ts`. Update both together.
- **Rollup externals**: any Node/native module used by the main process must be
  in `vite.config.ts` → `rollupOptions.external`.
- **Sentry + electron-log** initialize at the very top of `main.ts`, before
  dotenv/app imports.
- **CSP** is set in `electron/main.ts`. Adding an outbound host there is a
  product decision, not a detail.

## Environment Variables

All optional — see `.env.example`. The Anthropic API key is **not** an env var;
it is entered in Settings and stored encrypted.

- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — only for BigQuery OAuth
- `SENTRY_DSN` — optional crash reporting; telemetry is off when unset
